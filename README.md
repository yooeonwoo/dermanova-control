# 더마노바 관제센터

레아쥬·바이오폭스·711메디샷 직원용 공유포털입니다. 직원 열람에는 로그인이 필요하지 않고 공지, 행사, 공유 링크의 등록·수정·삭제는 관리자에게만 열립니다.

## 실행

Node.js 24.10 이상이 필요합니다.

```powershell
npm.cmd ci
npm.cmd run setup
npm.cmd start
```

http://localhost:3000 에서 확인하세요. 최초 설정이 생성한 관리자 비밀번호는 `.local/admin-password.txt`에 있습니다. `.env`의 `ADMIN_PASSWORD`를 바꾸고 서버를 다시 시작하면 비밀번호가 변경됩니다. `.env`와 비밀번호 파일은 Git에 포함되지 않습니다.

## 사용

- 홈: 중요 공지, 자주 쓰는 링크, 가까운 행사
- 이벤트 / 행사: 진행 중·예정·종료 탭, 상세 안내, 안내 페이지 공유
- 링크모음: 분류별 검색, 열기, 링크 복사, 안내문과 링크 함께 복사
- 공통 브랜드 정보는 개별 브랜드 필터에서도 표시
- 통합 검색: 제목, 설명, 본문, 담당팀, 브랜드로 검색 (`/` 단축키)
- 관리자: 공지·행사·링크 등록 및 편집, 홈 우선 표시, 종료·보관, 삭제
- 실제 데이터가 없을 때 빈 상태 안내. 하단 ‘예시 화면 보기’는 저장되지 않는 명시적 예시입니다.

모든 콘텐츠는 서버의 SQLite에 저장됩니다. 브라우저 저장소에 운영 데이터를 보관하지 않으며 재시작 후에도 유지됩니다. 직원 화면은 1분 간격과 창 복귀 시 정보를 갱신합니다. 행사 상태는 한국 날짜 기준으로 결정하고 종료일 당일까지 진행 중으로 표시합니다. 링크는 보관 처리하면 목록에서 숨깁니다. 기존 공유 주소는 계속 열립니다.

현재 등록한 링크 12개와 행사 3개는 `lib/initial-content.json`에 초기 자료로 포함했습니다. 새 환경에서 최초 실행하면 빈 데이터베이스에 한 번만 등록합니다. 기존 운영 데이터는 덮어쓰지 않으며, 관리자가 삭제한 자료를 재시작할 때 다시 추가하지 않습니다. 홈에는 온라인카다로그·세미나 신청링크·카카오채널 세 개를 고정 표시합니다. 즐겨찾기 기능은 없습니다.

## 팀 공유 및 배포

직원 공유 주소: https://dermanova-control.vercel.app

로컬 기본 실행은 본인 PC에서만 접근 가능한 `127.0.0.1`입니다.

Vercel 배포는 `vercel.json`과 `api/portal.js`를 사용합니다. **Vercel에서는 비공개 Blob 저장소**, 로컬 실행에서는 SQLite에 저장합니다. GitHub Pages 등 정적 호스팅만으로는 관리자 저장 기능을 사용할 수 없습니다. 물류 기능은 포함하지 않았습니다.

Vercel 프로젝트에 비공개 Blob 저장소를 연결하고 `ADMIN_PASSWORD`를 서버 환경변수로 설정합니다. 최초 자료를 `portal/content.json`의 `{ "records": [...] }`로 저장하며, 관리자 세션·로그인 횟수 제한은 별도의 비공개 `portal/security.json`에 저장합니다. 공개 API에는 행사·링크만 반환하고 세션과 저장소 토큰은 포함하지 않습니다. 수정 충돌은 Blob ETag로 감지하며, 재배포 후에도 등록·수정·삭제와 관리자 로그인이 유지됩니다. 운영 비밀번호는 변경 전과 동일합니다.

```powershell
vercel.cmd deploy --prod
```

환경변수 예시는 `.env.example`을 참고하세요.

- `HOST=0.0.0.0`: 호스팅이나 사내 네트워크에서 수신
- `PORT`: 수신 포트 (기본 3000)
- `ADMIN_PASSWORD`: 충분히 긴 고유 비밀번호
- `PUBLIC_ORIGIN=https://실제주소`: 편집 요청의 허용 출처, 마지막 `/` 없이 입력
- `COOKIE_SECURE=true`: HTTPS 운영에서 설정
- `DATA_DIR`: 재배포 후에도 유지되는 영구 저장 디렉터리

공유 화면과 `/api/content`는 공개 열람이므로 고객 개인정보·계정정보·비공개 링크를 등록하지 마세요. 관리자 비밀번호는 화면이나 클라이언트 코드로 전달하지 않습니다. 관리자 세션은 8시간 유지됩니다. 로컬에서는 서버 재시작 시 만료되며 Vercel에서는 비공개 저장소에 유지됩니다. 로그인 실패 횟수 제한과 동일 출처 요청 검증, 수정 충돌 감지를 적용했습니다.

백업은 서버를 중지한 상태에서 `data/portal.sqlite`를 복사하는 방법이 가장 간단합니다. 실행 중에는 SQLite 백업 도구를 사용하고 WAL 파일을 임의로 지우지 마세요.

## GitHub로 공유 링크 등록

`lib/link-registrations.json`에 제목, 자료설명(`description`), 브랜드, 분류, URL과 고유 ID를 넣고 푸시하면 Vercel 반영 후 링크모음에 저장됩니다. 홈에 올리지 않는 항목은 `pinned: false`로 등록합니다. 이 파일에는 공유 링크만 넣으며, 기존 관리자 로그인과 화면 등록 기능은 그대로 사용합니다.

등록한 내용은 운영 Blob 저장소에 반영하고 처리 이력을 함께 보관합니다. 같은 파일로 다시 배포해도 중복 등록하지 않으며, 관리자가 수정하거나 삭제한 항목을 같은 내용으로 다시 덮어쓰거나 복구하지 않습니다. GitHub 등록 내용을 변경해 다시 푸시하면 해당 변경분을 적용합니다. URL이 이미 등록되어 있으면 기존 ID와 별도로 입력한 상세 내용·담당자를 유지합니다.

## 확인

기존 운영통합센터 링크는 `operation_links` JSON 배열로 가져올 수 있습니다. `tags`에 문자열 또는 `{name}` 배열을 넣으면 해시태그를 상세 내용과 검색에 보존합니다. 브랜드를 명확히 지정한 해시태그가 없거나 여러 브랜드가 지정된 링크는 `공통`, 기존 분류와 정확히 일치하는 태그가 없으면 `업무·기타`로 가져옵니다. 설명과 고정 여부는 보존하고 삭제된 링크·잘못된 URL·중복 URL은 제외합니다. 먼저 확인만 실행할 수 있습니다.

```powershell
node scripts/import-links.js .local/links.json --dry-run
node scripts/import-links.js .local/links.json
```

실제 가져오기 전 SQLite 백업을 `data/backups/`에 저장합니다. 원본 운영센터 데이터베이스는 수정하지 않습니다. 가져온 자료는 현재 공유포털에서 로그인 없이 열람됩니다.

```powershell
npm.cmd test
node --check public/app.js
```

인증·공개 열람·저장 및 재시작 유지·수정 충돌·유효성 검사·로그아웃·로그인 횟수 제한을 검사합니다.

기술 참고: [Node.js SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html), [환경 파일 로딩](https://nodejs.org/api/environment_variables.html).
